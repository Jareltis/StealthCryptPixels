# StealthCryptPixel

StealthCryptPixel — консольная утилита на C# для встраивания зашифрованного файла в одно или несколько изображений. На выходе она сохраняет новые PNG-файлы с префиксом `stego_`; исходные изображения обычно остаются на месте.

Проект экспериментальный. Шифрование защищает содержимое файла, но само по себе не гарантирует, что скрытые данные нельзя обнаружить. В репозитории нет независимого аудита безопасности или опубликованных тестов на современных стеганоаналитических и ML-детекторах.

## Режимы

В программе есть два варианта встраивания:

- **V4** (`-c` / `-d`) использует LSB matching и распределяет данные по RGB-каналам всех изображений. Свободные позиции заполняются случайными битами. У этого варианта выше вместимость, но изменения затрагивают больше значений пикселей.
- **V5** (`-c5` / `-d5`) рассчитывает стоимость изменения пикселей по HILL-подобной модели и использует Syndrome-Trellis Codes (STC). Программа выбирает плотность встраивания автоматически: сначала пробует более низкую плотность и повышает её только если данные не помещаются. Длина шифротекста записывается в служебную область первой картинки. Это попытка уменьшить заметность изменений, а не гарантия устойчивости к стегоанализу.

Обе версии сжимают файл с помощью GZip и шифруют его AES-256-GCM. Ключ выводится из пароля с помощью Argon2id (64 MiB памяти, 3 итерации, параллелизм 1). Эти параметры заданы в исходном коде.

## Требования

- .NET 8 SDK или новее.
- NuGet-пакеты, указанные в `StealthCryptPixel.csproj`.
- Для сборки с используемой версией SixLabors.ImageSharp потребуется настроить лицензию ImageSharp согласно условиям поставщика. Поместите свой файл `sixlabors.lic` в корень проекта; не добавляйте личный файл лицензии в репозиторий.

## Сборка

```bash
git clone https://github.com/Yahasi/StealthCryptPixel.git
cd StealthCryptPixel
dotnet restore
dotnet build -c Release
```

Чтобы запустить встроенные тесты алгоритмов V5:

```bash
dotnet run -c Release -- -t5
```

Для публикации отдельного исполняемого файла под Windows x64:

```bash
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Готовые файлы будут в `bin/Release/net8.0/win-x64/publish/`. Для другой платформы укажите соответствующий runtime identifier, например `linux-x64` или `osx-arm64`.

## Использование

Пароль можно ввести скрыто в консоли — это предпочтительнее, чем передавать его аргументом командной строки: аргументы могут остаться в истории оболочки или быть видны другим процессам.

### Скрыть файл (V4)

```bash
dotnet run -c Release -- -c secret.zip cover1.png cover2.png
```

Программа запросит пароль и его подтверждение. Рядом с изображениями появятся `stego_cover1.png` и `stego_cover2.png`.

### Извлечь файл (V4)

```bash
dotnet run -c Release -- -d stego_cover1.png stego_cover2.png
```

После ввода пароля файл будет сохранён в текущую рабочую папку под именем `Decrypted_<исходное_имя>`. Если файл с таким именем уже существует, текущая реализация может его перезаписать; для извлечения лучше использовать отдельную пустую папку.

### Скрыть и извлечь файл (V5)

```bash
dotnet run -c Release -- -c5 secret.zip cover1.png cover2.png
dotnet run -c Release -- -d5 stego_cover1.png stego_cover2.png
```

V5 сохраняет восстановленный файл в текущую папку под исходным именем. Перед извлечением убедитесь, что файл с таким именем не существует: текущая реализация может перезаписать его.

Вместо `dotnet run -c Release --` можно использовать опубликованный `StealthCryptPixel.exe` или соответствующий исполняемый файл для вашей платформы. Полный список режимов выводится при запуске без аргументов.

## Форматы и ограничения

- В качестве изображений-доноров принимаются PNG, JPEG (`.jpg` / `.jpeg`) и BMP. Результат всегда сохраняется в PNG. JPEG-донор поэтому меняет формат, а размер файла может заметно увеличиться.
- Изображения обрабатываются как RGB. Если исходный файл содержит прозрачность, она не сохраняется в выходном PNG.
- При извлечении передавайте **все изображения в том же порядке**, в котором они были переданы при создании. Не переставляйте их местами и не исключайте отдельные файлы: обе версии используют первый файл для служебных данных и зависят от полного набора.
- Не изменяйте полученные PNG. Пересохранение с потерями, изменение размеров, конвертация в JPEG или обработка сервисом, который перекодирует изображения, могут повредить скрытые данные.
- Используйте разные имена для изображений-доноров. Если два входных файла в одной папке имеют одинаковое имя без расширения, они могут претендовать на один и тот же путь `stego_*.png`.
- Программа загружает содержимое файла и изображения в память. Для больших файлов и изображений потребуется соответствующий объём RAM.
- `-t5` проверяет внутренние тестовые векторы и отдельные части алгоритма V5, но не заменяет полноценное тестирование всего приложения.

При извлечении параметры Argon2id читаются из встроенного заголовка. Код допускает значения вплоть до 1 GiB памяти и 64 итераций, поэтому специально сформированный файл может вызвать высокую нагрузку на память и процессор. Пока эти пределы не ужесточены, не обрабатывайте наборы изображений из недоверенных источников.
